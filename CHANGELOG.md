# Changelog

What changed in each release of Amuse, for the people who run it. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/) (before 1.0, a minor version may change how things work).

## [Unreleased]

### Upgrade notes
- **Your data moves into one database on first start.** The conversation history, chats, permissions, password, defaults and the index of sent files are imported from the old files into `amuse.db` in the data folder, which is checked against the old files before they are renamed to `<name>.bak` (`events.jsonl.bak`, `chats.json.bak`, …) and kept, never deleted. Nothing to do; delete the `.bak` files once you are happy. The keys, the model choice and the sandbox's credentials go into the Vault (below).
- **Never run an older version of Amuse on this data.** It does not know the database: it would start with no history and no password, and the next visitor could set one. Amuse refuses to start if the old files turn up beside the database again (an interrupted update, or an older version that was run), and its address says what to do; `amuse-admin retire-old-files` finishes an interrupted rename, once the files are exactly what was imported.
- If the move cannot finish, Amuse does not start, and its address shows a page that says which step failed and what to do (the server's log has the details); your data is as it was.
- To go back to the version before this one anyway, after stopping Amuse: delete `amuse.db`, `amuse.db-wal` and `amuse.db-shm`, rename every `*.bak` back to its name (`events.jsonl.bak` → `events.jsonl`, `chats/<id>.jsonl.bak` → `chats/<id>.jsonl`, …), and start the older version. What was said since the update is lost; export it first with `amuse-admin export`. To get back your keys and the sandbox's credentials too, first run `amuse-admin restore-secret-files --yes` (it writes `keys.json` and `sandbox-secrets.json` out again from their sealed copies, which needs the Vault's key), rename `models.json.bak` to `models.json`, and note that the older version has no Vault: what you stored only there is not in it. To undo only the last update's changes to the database, the copy Amuse made before it is in `backups/` (`*-pre-migrate.db`).
- **Forgot the password** is now `docker compose exec amuse amuse-admin reset-password` (deleting `access.json` no longer does anything). Run `amuse-admin` as the container's default user.
- Before an update that changes the database, Amuse copies it to `backups/` in the data folder, and keeps the last five such copies.
- **Back up the Vault's key.** The Vault (see below) seals your secrets with a key in a volume of its own (`vault-key`, mounted at `/secrets/amuse-store`), apart from your data and from the browsers' `secrets` volume, so removing that one cannot destroy it. Run `docker compose up -d --build` once so that the volume's folder is made, and copy the key somewhere safe after the first start has made it (`docker compose cp amuse:/secrets/amuse-store/store.key .`): without it nothing in the Vault can be opened, and Amuse will not start. If it is lost for good, `amuse-admin reset-vault --yes` empties the Vault so a new key can be made. Outside Docker, `AMUSE_SECRETS_DIR` names the folder; Amuse stops at start if it is not there.
- **`keys.json` and `sandbox-secrets.json` are taken into the Vault and deleted.** They held your keys and the sandbox's credentials in the open, so no `.bak` of them is kept: once the move is checked they are deleted, and the database keeps a copy of each sealed with the Vault's key. `models.json` (the model choice) is renamed to `models.json.bak` like the other old files. To go back to the version before this one, run `amuse-admin restore-secret-files` first (it writes the two files out again), then follow the steps above; `amuse-admin forget-secret-files --yes` deletes the sealed copies once you are sure. Plaintext leftovers beside them (`keys.json.tmp`, from a write cut short) are deleted with them; a `keys.json.bak` or `sandbox-secrets.json.bak` that an older Amuse left is not touched, only named in the log: delete it yourself.

### Added
- What the server keeps (the history, chats, permissions, password and the rest) is in one database file: a crash can no longer leave several files half written, Amuse's memory use grows with what your chats hold, not with every event ever recorded (the history is read as it is replayed, not held as a file), and the file can be copied while Amuse runs.
- `amuse-admin`, a command on the server: list what an update will change before it runs (`migrate --dry-run`), export a chat's history as JSONL (`export`), and reset the password. A chat deleted while Amuse is still working in it no longer stops the server.
- A Vault (Settings › Vault) for the long-term secrets Amuse uses for you: API keys, tokens, passwords and key files such as a Google service account's JSON. Each entry has plain fields you and Amuse can see (an account id, a username), secret fields that are encrypted and never shown back (you replace them), and a note. Where a secret goes is set apart from what it is: a variable or file in the sandbox, or one of Amuse's own services. Two limits to know: Amuse masks a secret shorter than 6 characters nowhere (it would mask ordinary words), and a URL or host kept as a plain field is not told from a secret: put anything that grants access in a secret field.
- Amuse looks in the Vault before it asks you for a key (`list_secrets`), and asks on a card in the chat: a long-term secret to keep (Amuse fills in the details it can read, such as a username, and shows them to you; everything you type on the card is kept encrypted and Amuse never sees it), or a temporary login or verification code that is typed straight into the terminal waiting for it and kept nowhere. The first time Amuse wants an existing secret in the sandbox, it waits for your Allow or Deny; a second name for it needs nothing. Secrets in the sandbox are masked as `[secret: …]` in what Amuse sees, including what it reads of your files, and each secret shows when and where it was last used (and only the end of a long one, never of a short one).
- When its work needs a model provider's or Composio's key that is not set up, Amuse asks for it on a card in the chat that opens the same sign-in as Settings, instead of sending you there.
- Amuse can write to you in the middle of long work: it answers a message you send while it is busy, and says what it is starting before something that takes a while, instead of going quiet until it is done.
- The browser can run on the chat's model ("Same as chat", now the default), as background work already could; Settings says so when the chat's model cannot see pictures.
- On a phone, swipe to open and close the sidebar and the work computer: right on the chat opens the sidebar (more readily from the left edge), left opens the viewer the laptop button opens, and the opposite swipe closes whichever is open, anywhere on it, a desktop you are only watching and the terminal included. The page follows your finger and settles open or closed by how far it came and how fast you let go, on the same curve as the buttons (it snaps with reduced motion). Vertical scrolling is never taken over, and the gesture stays out of sheets, text fields, selected text (the terminal's too), code blocks that can still scroll sideways, and the screen edges your phone uses for Back. While you control the desktop it keeps every touch for itself, and the viewer closes by a swipe from its left edge strip, its header or its switch. On a phone the open sidebar's button moves to its top right as before and turns into the round close X the viewer and sheets have (it was a collapse icon). (#43)
- Connections: services that take your own key instead of Composio's login (Cloudflare wants an API token) can now be connected. Amuse reads how the service signs in; for a key it shows one field, named as the provider names it, in Settings › Connections and in the Connect card. The key goes from your browser through the server to Composio, which holds it and checks it with the provider: Amuse stores it nowhere (no file, database or log), and the agent never sees it and cannot type it for you. (#46)

### Changed
- Connection errors say what happened: "Composio could not be reached" is only for no answer or a server error (5xx); a refused key, an app Composio does not know (404), a rate limit (429), other refusals, an unexpected answer, and an app that needs your own key each have their own message. (#45)
- Long chats cost less and answer sooner: each turn is laid out so the model's provider can reuse what it already read of the chat, and the conversation Amuse is shown changes at its end instead of from its start (older parts move to a shorter form a few thousand characters at a time, not with every message). (#37)
- Credentials given to the sandbox, the model, speech and Connections keys, and the model choice now live in the Vault, in the database, encrypted with a key kept apart from your data (see the Upgrade notes: back that key up). They move over once on the first start, and the files that held secrets in the open are deleted, not kept as backups.
- Settings › Sandbox no longer lists credentials: they are in Settings › Vault. The "Saved logins" section is now "Browser data": each site's cookies and storage that keep you signed in (no passwords).
- Settings › Models gives each role (chat, browser, background) a group of its own, with a row for its provider, its model and its thinking, each named; the provider is chosen first, so the same model from two providers is no longer listed twice. The thinking row is always there, and says when a model has to be chosen first or does not think.
- Sheets close with the same round button as the rest of the app, and a task's details open in a wider sheet.
- Buttons with words look the same everywhere: one height for a button in a row or card and one for a sheet's, one way to show it is disabled, pressed or focused. A destructive action in a row (Sign out, Delete, Remove, Reset) is the grey pill with red text that Schedules had, so Settings › Saved logins and Sandbox match it, and "are you sure?" sheets are all one design. The buttons on Amuse's cards are a little smaller than before, and a connection card that is already connected or dismissed shows that as text instead of a greyed button.
- The terminal's lines are a little taller, so Chinese characters are no longer cut off at the top.

### Fixed
- The status under Amuse's avatar glides to its new size and changes its line with a crossfade, instead of snapping and flickering; the brief "responding" line between two tools no longer flashes in.
- The chat keeps its least width when the window is made narrower after the browser panel was dragged wide; widened again, the panel comes back to the width it was dragged to.
- Amuse can cancel a schedule you no longer want: it looks the schedules up with their full ids instead of going by what it remembered of them.
- On a wider screen, the Amuse avatar flies into its panel and back again when the panel opens and closes.

## [0.1.0] - 2026-10-21

The first release.

### Added
- Chat with Amuse in a main chat and side chats, on a desktop or a phone (an installable web app), in English or Simplified Chinese.
- A pool of real Chrome browsers Amuse operates for you, which you watch live and take over; logins you make there are kept per site.
- Connections to Gmail, Calendar, Slack, GitHub and many more through Composio, with your own key; several accounts per service.
- Permissions per connection and kind of action, and for the browser by kind of action with exceptions per site.
- A sandbox: a Debian machine of Amuse's own, reaching the public internet only, with terminals (herdr) shared with you and credentials that never pass through the chat.
- Memory, goals, schedules and skills; voice input through OpenAI, Groq, Fireworks or your own speech server.
